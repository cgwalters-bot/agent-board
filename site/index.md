agent-board reads a GitHub project board, its issues and their pull
requests, and keeps them in order: it previews bookkeeping repairs,
decides what job an issue should get, dispatches that job once with a
record on the issue, and follows the pull requests that come back. It
does not run agents itself, and nothing it derives from board text is
write authority: repairs are proposals for an independent check, and
writes happen only where an operator asks for them.

It is for maintainers who want coding agents to pick up issues from an
ordinary project board, with the bounds, tokens and records kept where
people already look.

## Where it fits

Three repositories share the work; each holds what the others must not.

- **agent-board** (this site): the board's typed interface and controller. Reads the board, plans and dispatches jobs, follows their pull requests; see the [overview](../README.md) and [commands](../README.md#commands).
- **[agentic-job](https://cgwalters-forge.github.io/agentic-job/)**: runs one agent job on a hardened CI host and checks what it hands back before anything with a write token acts on it. agent-board's dispatches target its workflow.
- **[tracker](https://github.com/cgwalters-forge/tracker)**: the trusted caller. Its default branch holds the bounds, the configuration agent-board reads and the token; its [polling job](https://github.com/cgwalters-forge/tracker#the-pull-request-poll) runs agent-board on a schedule.
