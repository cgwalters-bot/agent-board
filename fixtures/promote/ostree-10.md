## Executive summary

prepare-root fails to build on Amazon Linux 2023 (ostreedev/ostree#3696). With glibc 2.34 there, the `<linux/mount.h>` pulled in by `<linux/btrfs.h>` defines MS_* macros that break glibc's `<sys/mount.h>` enum. This change includes `<sys/mount.h>` first. It also teaches `ci/gh-install.sh` to set up AL2023 containers (the srpm builddeps plus test helpers) so the container test matrix can cover AL2023.

Verified in an AL2023 rootfs (podman containers don't start in this sandbox, so I used an exported image rootfs under `podman unshare` + chroot). I reproduced the reported error with the old include order. With this change, the CI job's own steps pass: `gh-install.sh`, then `gh-build.sh --without-selinux` as the unprivileged `builder` user (build, make check with 949 pass/38 skip, distcheck, install). Not verified: an actual GitHub Actions run.

The matrix entry is **not** in this diff, because this run can't change `.github/`. Add it to `.github/workflows/tests.yml` at the end of the `tests` matrix `include:` list:

```yaml
          # Amazon Linux 2023 has glibc 2.34 with new kernel headers,
          # which catches <sys/mount.h> vs <linux/mount.h> conflicts.
          #
          # https://gallery.ecr.aws/amazonlinux/amazonlinux:2023
          - name: Amazon Linux 2023
            image: public.ecr.aws/amazonlinux/amazonlinux:2023
            pre-checkout-setup: |
              dnf -y install git
            # The build dependencies install an SELinux policy, so the
            # libarchive SELinux test would try to set security.selinux as
            # the unprivileged builder user and fail.
            configure-options: >-
              --without-selinux
```

Without `--without-selinux`, `/libarchive/selinux` fails: AL2023's build deps hard-require selinux-policy-targeted, so the test runs and gets EPERM setting security.selinux as a non-root user.
