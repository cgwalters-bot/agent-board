# A day's agent spend

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

`agent-board cost --config FILE --date YYYY-MM-DD` reports what one UTC day's
agent runs used and cost, by kind, model, repository and item, as
`agent-board/cost-day/v1` JSON ([schema](cost-day.schema.json)); `--human`
prints a short table instead (agent-board#441). It is read-only. Unlike the
[budget tree](pass.md#budget-tree), it counts every run with an agentic-job
artifact, reviews included, which are no board items: a review's is named
`agent-run`, a dispatched run's `dispatch-KIND-agent-run`
(`dispatch-implement-agent-run`, `dispatch-triage-agent-run`, ...).

The configuration is the [pass's](pass.md#one-configuration-file), from a
trusted default-branch checkout. Cost reads its `workRepositories`, `follow`
and `dispatchRepo`, whose runs count, and its `prices`. `GH_TOKEN` reads their
Actions runs and artifacts.

## What it reads

For each repository, the completed workflow runs created on the day
(`actions/runs?created=DATE&status=completed`; GitHub lists at most 1000 for
one filter, so a day with more is listed in halves of it, down to an hour),
and, where there are any, the repository's artifacts, all names, newest
first, back to the first one created before the day began (at most 2000,
other workflows' artifacts included). Of those, the ones named `agent-run`
or ending in `-agent-run` count, one per run: where a run has several, the
shortest name, and of a re-run's same name the newest attempt's. A run with
such an artifact is downloaded, at most 4 MiB, and only the `summary.json` at
the top of its zip is read, at most 64 KiB unpacked, stored or deflated. From
the summary, `tokens` (`input`, `output`, `cache_read`, `cache_write`; a
missing count is 0), `model`, `repo`, `item`, `outcome`, `duration_s` and
`workflow`, the last only where nothing else names the run's kind. A run
whose artifact expired, is too large or has no readable summary is listed under `unread` with the reason, not counted; a request that
fails, the bounds below or the cache fail the whole day instead, so that a
report never leaves out a run for a passing reason. A read sends at most 1000
requests, the last 5 of them only for publishing, takes at most 10 minutes,
and sends nothing more once a request is refused under a rate limit.

`--cache DIR` keeps each summary read in `DIR/RUN_ID.json`, and a run whose
summary is there is never downloaded again: a later read of the same day costs
only the listings.

A run's kind is the first of `review`, `implement`, `triage`, `fix`, `planning`
(`plan`) and `supervisor` (`supervis`) that a word of its artifact's prefix
(`dispatch-fix` of `dispatch-fix-agent-run`) starts with, else a word of its
workflow file name, each split at `-`, `_` and `.`, so a review's plain
`agent-run` from `review.yml` is `review`; otherwise the one the first word of
its title starts with, as in the pass's `implement OWNER/REPO#N (pool)`;
otherwise, from the summary's `workflow`, `implement` for `branch` and
`triage` for `analysis` (each of which also serves the other of its pair, fix
and planning, which only the name or title tells apart); otherwise `other`.
Its repository
is the summary's `repo` where that is a repository name, else the one it ran
in; its item is `REPO#N` for a numeric `item`, else the summary's text.

## Prices

`prices` in the pass configuration maps a model, as summaries name it, to its
list prices in US dollars per million tokens:

```json
"prices": {
  "anthropic/claude-x": {"input": 3, "cached_input": 0.3, "output": 15}
}
```

Each price is 0 to 10000. A run's cost is `input` for its input and
cache-write tokens, `cached_input` for its cache-read tokens and `output` for
its output tokens; the four counts are taken as disjoint, so where a provider
counts cached tokens within input too, the cost is an upper bound. A run whose
model has no price is unpriced: its `usd` is null, it counts toward its
groups' `unpriced_runs` and tokens, and its tokens are listed by model under
`unpriced`. It is never counted as $0, and a group none of whose runs is
priced has a null `usd`.

## The report

`agent-board/cost-day/v1` has the `date`, the `repositories` read, `totals`,
and the groups `by_kind`, `by_model` and `by_repository`, each a map of name
to `{runs, tokens, usd, unpriced_runs}`; `top_items`, the ten items with the
highest priced cost, the group's fields with `item`; `unpriced`, by model,
`{runs, tokens}`; `runs`, each `{id, url, kind, repo, item, model, tokens,
usd, outcome, duration_s}`, by run id; and `unread`, each `{id, url, reason}`.
Dollar amounts are rounded to a hundredth of a cent. An example, the
recorded day the tests read, is
[fixtures/cost/report-2026-10-28.json](../fixtures/cost/report-2026-10-28.json).

## Publishing

With `cost` set in the pass configuration (absent, off), the pass publishes
the reports as its last stage:

```json
"cost": {"hourUtc": 6}
```

From `hourUtc` (0–23) each day, it lists `cost/` on the `data` branch of
`epics.repository`, one request, and reads and publishes each of the last
seven days before today whose `cost/YYYY-MM-DD.json` is not there: yesterday's
once a day, and the whole week on the first run, oldest first. The files go in
one commit through the git data API (a tree with the files' contents on the
branch's tree, a commit, and the branch moved, without force), which creates
the branch where it is missing. The branch is always `data`, never one the
configuration names, so never the default branch; its token, the pass's
`GH_TOKEN`, needs contents write on that repository, and the branch should be
outside rulesets that hold the default branch. The reports name the runs,
items and models of every configured repository, private ones included, so
publish them only to a repository whose readers may see those. A day that cannot be read is a
`cost error:` line, and the days that could are still published; the next
pass tries again.

The stage is one `--max-writes` step. A preview lists what is published and
says what it would publish, reading no runs. Its requests are bounded apart
from the pass's own (1000, the last 5 kept for the commit), so that a week's
backfill takes none of the other stages' budget; its time is what is left of
the pass's 15 minutes, and the commit may take 2 minutes past them. Once
either bound is spent, the days read so far are published and the rest left
to the next pass. It is skipped once a rate
limit has stopped the pass. `cost.cache` is a directory, which must exist,
kept as `--cache` is; like `state`, it saves requests only where the caller
keeps it between passes.

Runs still in progress at `hourUtc` are not in the day's report, and it is not
rewritten later: choose an hour after the day's runs have ended.
